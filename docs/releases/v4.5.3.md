# GitDash v4.5.3 — release notes

Released 2026-09-28. A performance and correctness release for the contributor profile. Upgrading needs
no new settings. Helm chart 0.7.2 declares appVersion 4.5.3. See [`CHANGELOG.md`](../../CHANGELOG.md)
for the itemised list.

## Why

Opening a contributor profile could take 20 seconds or more. The route walked up to 30 of the owner's
repositories, and for each one listed recent pull requests, listed the person's commits and fetched
reviews on up to 10 pull requests — about 360 GitHub requests, five repositories at a time. Once the
5-minute cache expired, the next visitor waited for all of it again.

## What changed

- **Three searches instead of a repository walk.** The profile is now built from three GitHub searches
  that run in parallel: the pull requests the person authored (with sizes and the reviews each received),
  the pull requests they reviewed (with their own reviews), and their commits. Search covers every
  repository the token can see, private ones included.

  | Same person, same network | 4.5.2 | 4.5.3 |
  |---|---|---|
  | Time, nothing cached | 17.4 s | 3.5 s |
  | GitHub requests | 227 | 6 |

- **Serve the last result while refreshing.** `withCache` gained a `staleSeconds` option: after the TTL,
  callers get the previous value immediately and a single background refresh replaces it (kept alive
  after the response with Next.js `after()`). Contributor profiles use a 30-minute TTL and a 6-hour stale
  window. The Refresh button bypasses the cache on this route.

## Numbers on the profile will change

These are corrections, not regressions:

- **Pull requests and reviews go up.** 4.5.2 only scanned each repository's 30 most recently closed pull
  requests, so it missed most of an active contributor's work (in the measurement above: 10 → 61 pull
  requests, 37 → 191 reviews). Open pull requests are now counted as opened too.
- **Average pull request size** was always 0 — the list endpoint never returned additions or deletions.
- **The funnel's "reviewed" and "approved" steps** were always 0: they counted the person's reviews of
  their own pull requests. They now count reviews other people left on them.
- Commit counts are unchanged (104 → 105 in the measurement; the search counts one more recent commit).

## Notes for operators

- Search has its own GitHub rate limit (30 requests a minute per token). One profile uses at most two
  pull-request searches and up to five commit-search pages; the longer cache keeps repeat views off it.
- Commit search indexes default branches only — the same scope as before.
