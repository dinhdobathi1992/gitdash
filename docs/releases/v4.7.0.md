# GitDash v4.7.0 — release notes

Released 2026-09-29. **Team insights v2**: one window for the whole page, "What stands out", human-review
KPIs, account links and an org workday. Helm chart 0.7.6 declares appVersion 4.7.0. This release adds
database migration v12. See [`CHANGELOG.md`](../../CHANGELOG.md) for the itemised list.

## Why

The v1 Team page mixed windows (the last 60 closed pull requests, reviews for 30 of them, workload over
42 days), showed the median of each person's average as "cycle time", counted bot and self reviews as
reviews, and left the reader to work out what mattered. Some engineers also use two GitHub accounts, so
their own reviews looked like someone else checked their code.

## What changed on Team insights

- **One window**, 30 or 90 days, for every section (`?days=90` survives reload and sharing).
- **What stands out** — findings computed from the numbers, worst first, each linking to its section:
  after-hours work, one reviewer doing most reviews, merges without a human review, commits over the size
  limit, pull requests with too many commits, self-merges. Only findings with evidence appear.
- **KPIs**: merged (and opened in the window — a different set), the true median open → merged,
  **reviewed by a human** (a submitted approve / request-changes / comment by someone who is neither a bot
  nor the author), reviewer bus factor over human reviews (same 50% rule as before), self-merged.
- **Who reviews whom** by pull request; a heatmap from 4 reviewers. **Workload to watch** with bars and the
  fixed limits (30% after hours, 25% weekends, 4 open pull requests). **People** table with author,
  reviewer and habit columns and CSV export of the columns you are granted. **Include bots** switch — bots
  never count toward team numbers.
- **Working habits** layout: commits over the limit by reason, the largest commit, oversized commits
  grouped by pull request.

## Account links

Admins (organization mode) see "Are A and B the same person?" when two logins share a name stem and one
reviewed the other. **Link accounts** counts them as one person on every Team page: pull requests,
reviews, commits and working habits add up, and reviews between them become self-reviews.
**Different people** stops the suggestion. Settings → Account links lists every link and dismissal with
Unlink / Undo; every change is in the audit log. **Links change numbers only, never access** — an
engineer's own working-habits view stays their own login.

## Workday — numbers change on upgrade

After hours and weekend are now read in the organization's workday, set in **Settings → Team insights**
(time zone + hours). **Default: Asia/Saigon 08:00–19:00** (it was UTC 09:00–18:00). This applies to Team
insights **and each repository's Team tab**, so after-hours and weekend percentages there change on
upgrade. The contributor profile's commit-hour chart and the `afterhours_commit_pct` alert still use UTC
09:00–18:00 (follow-up).

## Checked against GitHub

Local build, Docker Postgres, read-only GitHub. An independent script re-counted every KPI from GitHub
GraphQL with different page sizes and its own implementation of the rules:

| Repository · window | Merged | Reviewed by a human | No human review | Self-merged | Median | Mismatches |
|---|---|---|---|---|---|---|
| tesda-backend · 90 d | 99 | 49 | 50 | 88 | 1.7 h | 0 (incl. 5 reviewers' counts) |
| tesda-backend · 30 d | 29 | 15 | 14 | 26 | 3.5 h | 0 |
| gitdash · 90 d | 30 | 14 | 16 | 30 | 0.1 h | 0 |
| gitdash · 30 d | 8 | 3 | 5 | 8 | 0.1 h | 0 |

Cost of the windowed fetch: **tesda-backend 90 d = 3 GraphQL points, 4.3 s cold, 0.1 s warm, 46 KB of
cached facts** (the 90-day window is read as three 30-day slices in parallel). Linking `dinhdobathi3` to
`dinhdobathi1992` turned gitdash's 14 human reviews into self-reviews; unlinking restored them.

## Notes for operators

- **Back up the database before upgrading.** Migration v12 runs on the first request after deploy. It is
  additive: tables `identity_links`, `identity_distinct`, `team_settings`.
- Set the workday in Settings → Team insights if your team is not on Asia/Saigon 08:00–19:00.
- The windowed contributors data uses GitHub GraphQL search (a separate quota from REST) and is cached per
  repository for 10 minutes, shared by everyone who can see the repository.
- The workload cache key changed, so each repository's workload is fetched once afresh after the upgrade.
- GitHub search returns nothing for an organization whose SSO has not authorized the viewer's token; the
  page then says so instead of showing empty numbers as fact.
