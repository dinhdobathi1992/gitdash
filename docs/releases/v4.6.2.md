# GitDash v4.6.2 — release notes

Released 2026-09-29. One fix to the nightly pull-request sync. Helm chart 0.7.5 declares appVersion
4.6.2. No database migration. See [`CHANGELOG.md`](../../CHANGELOG.md).

## What was wrong

For each pull request the sync records when it was first reviewed. A review that is still **pending**
has no submission time. The calculation started from the first review's time and fell back to an empty
string when it had none, so a pull request whose first review was pending stored `""` as a timestamp.
Postgres rejected it, the whole page of 100 pull requests failed in one transaction, and the repository
failed the same way on every run — it could never complete its backfill. Found on `adi-tesda-ds` the
night 4.6.1 shipped (`invalid input syntax for type timestamp with time zone: ""`).

## What changed

Pending reviews are ignored. The first review is the earliest review that has actually been submitted,
or none.

## Notes for operators

Nothing to do. The next nightly run (or a manual run of `/api/cron/sync-pr-facts`) completes the
affected repositories. Until then their people alerts stay quiet, as for any repository whose backfill
is incomplete.
