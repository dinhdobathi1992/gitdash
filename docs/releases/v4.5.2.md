# GitDash v4.5.2 — release notes

Released 2026-09-27. A documentation release: nothing in the application changed, so upgrading is
optional and needs no new settings. See [`CHANGELOG.md`](../../CHANGELOG.md) for the itemised list.

## Why

The 4.5 line changed a lot at once — a new interface, GitHub API caching and organization-mode access
control — and the built-in documentation and README still described 4.2. They now describe the app as it
is, with screenshots taken from a live instance.

## What changed in the docs

- **New sections:** Quick start, Access control (groups, grants, rollout, and why sign-in can be refused),
  and Caching & rate limits.
- **Features** follow the app's sidebar, one page per screen, each naming the feature switch that controls
  it — including the repository Workflows and Pull requests tabs added in 4.5.0.
- **Corrections** that could mislead someone running GitDash:
  - DORA change-failure-rate levels are ≤5% Elite, ≤15% High, ≤30% Medium (the docs said 5/10/15%).
  - Deploy frequency, lead time and hotfix detection work from the last 30 releases / 60 pull requests,
    and hotfixes are matched on `hotfix`, `revert`, `fix-prod` or `emergency` branches or "Revert" titles.
  - The Docker image is `dinhdobathi/gitdash`; the history sync runs nightly, not every 15 minutes; demo
    data still requires sign-in.
  - Fine-grained tokens can read organization data when the organization is the resource owner.
  - The API reference now covers the admin endpoints, issue creation and the organization-mode error codes.
- **README** rewritten to match.
